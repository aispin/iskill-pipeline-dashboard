# 短视频操盘可视化交互（可视化操盘台）方案

> 状态：待用户确认 · 2026-09-30
> 定位：专家团的底层技能（不暴露给用户直接调用），iskill-viral-dashboard

---

## 1 背景与痛点

| 现状 | 问题 |
|---|---|
| 各技能产物是 markdown（选题/拆解/文案/预检） | 普通用户不会去翻文件，产物"落了盘但看不见" |
| 决策过程在 agent 聊天流里 | 六步流程是黑盒，用户不知道团队"正在干嘛、进行到哪" |
| 选卡/确认等交互全靠聊天打字 | 对非技术用户门槛高 |

## 2 可行性结论：**可行，且与现有架构天然契合**

- 工作流本就是「文件即接口」（选题/ 拆解/ 文案/ 成片/ 四个目录）——dashboard 只需**监听这些目录 + 一个事件流水文件**，就能实时呈现全过程，**不侵入任何现有 skill 的逻辑**
- 全链路本地运行（node + vite dev server / 静态构建），无外部服务依赖
- 关键设计：**agent 侧零网络调用**——事件用「追加 JSONL 文件」上报，沙箱最稳（避开 curl/代理的一切坑）

## 3 架构设计

```
┌─ 专家团（主理人+成员）─┐
│  每阶段起止/产出落盘时          │
│  echo >> .pipeline/events.jsonl│  ← agent 唯一动作：追加一行 JSON
└──────────────┬─────────┘
               │ chokidar 监听
     ┌─────────▼──────────┐
     │  Node server (express + ws)          │
     │  · 监听 events.jsonl → WebSocket 广播│
     │  · 监听 选题/拆解/文案/成片 四目录    │
     │  · GET /api/file 读取产物内容         │
     │  · 决策落盘 .pipeline/decisions/*.json│
     │  · 托管 web/dist 静态资源            │
     └─────────┬──────────┘
               │ WebSocket
     ┌─────────▼──────────┐
     │  React 仪表盘（浏览器打开）          │
     └────────────────────┘

决策往返（页面交互闭环）：
页面点选卡片 → server 写 .pipeline/decisions/<id>.json
→ 主理人 bash 轮询该文件（sleep 循环，带超时）→ 拿到用户选择继续流程
```

**事件协议**（JSONL，每行一个事件）：
```json
{"ts":"...","type":"phase_start","phase":"teardown","member":"闻热点","title":"对标搜寻中"}
{"ts":"...","type":"artifact","path":"拆解/2026-09-30-xx-拆解.md","kind":"markdown","member":"闻热点"}
{"ts":"...","type":"decision_request","id":"pick-teardown","title":"选一条对标参考","options":[{"id":"1","label":"...","detail":"..."}]}
{"ts":"...","type":"phase_end","phase":"teardown","summary":"..."}
{"ts":"...","type":"pipeline_done","artifact":"成片/xxx.mp4"}
```

## 4 页面规划（单页应用，四个区域）

1. **团队栏**：4 成员卡片（头像/职责/实时状态 idle·工作中），粉品红主题对齐 06-ContentCreative
2. **流水线时间线**：六步横向进度条，当前阶段高亮 + 动画，完成阶段打钩
3. **事件流**：实时滚动的动态 timeline（谁在做什么、产出了什么）
4. **产物展示区**（核心价值）：
   - markdown 精美渲染（选题卡/拆解报告/文案/预检报告，带排版设计）
   - 成片 mp4 内嵌播放器、素材图片网格预览
   - **决策面板**：收到 decision_request 时弹出卡片选择按钮，点选即回传

## 5 技术栈（全部 @latest）

## 6 目录结构（遵循项目约定：ISkills git 仓库 + 软链）

```
ISkills/iskill-viral-dashboard/
  SKILL.md            # 底层技能：启动方式 + 事件协议 + 决策文件约定
  server/index.mjs    # express+ws+chokidar，单文件 ~200 行
  web/                # Vite React TS 项目（构建出 dist 由 server 托管）
  bin/dashboard.mjs   # 启动入口：node bin/dashboard.mjs --workspace <目录> [--port 5188]
```

## 7 与专家团的集成（最小侵入）

- **主理人 MD 增加一节「操盘台契约」**：任务开始 → 后台启动 dashboard → 每阶段起止/产物落盘追加事件 → 决策请求写事件后轮询决策文件
- **4 个成员 MD 零改动**（主理人是信息中转枢纽，统一由它上报）
- dashboard 未启动/崩溃 → 主理人**静默跳过**，绝不影响主流程（尽力而为可视化）
- 技能不进成员 skills 列表、不给用户触发词——只有主理人底层调用

## 8 实施步骤

| 阶段 | 内容 | 产出 |
|---|---|---|
| P0 | 脚手架：Vite React Tailwind 初始化 + server 骨架 + 事件协议定稿 | 可 npm run dev |
| P1 | 服务端：JSONL 监听→WS 广播、产物目录监听、/api/file、决策落盘 | 事件能推到浏览器 |
| P1 | 前端：团队栏 + 六步时间线 + 事件流 | 核心可视化可用 |
| P2 | 产物渲染：markdown 美化 + 成片播放器 + 图片网格 | 产物"看得见" |
| P2 | 决策面板：页面选卡 → 决策文件 → agent 轮询闭环 | 页面可交互 |
| P3 | 打磨：主题/动效/空态 + 全链路实测（拿农场选题真跑一遍） | 验收 |

## 9 风险与对策

| 风险 | 对策 |
|---|---|
| npm 安装需网络（沙箱） | 失败则配 registry 代理重试；依赖只装一次 |
| agent 忘记追加事件 | 主理人 MD 写成铁律 + 事件追加是单条 echo，成本极低 |
| 决策轮询阻塞对话 | 轮询带 5 分钟超时，超时回退聊天确认 |
| 端口冲突 | 默认 5188，占用自动 +1，最终地址回传给用户 |
| dashboard 挂了 | 主流程完全不受影响（静默跳过） |

## 10 验收标准

1. 用户对专家团说需求后，浏览器打开操盘台能看到：团队状态 → 六步时间线推进 → 事件流滚动 → 产物实时出现
2. 对标选卡环节，用户在**页面**上点选，主理人收到选择继续流程
3. 关掉 dashboard，专家团主流程照常跑完
